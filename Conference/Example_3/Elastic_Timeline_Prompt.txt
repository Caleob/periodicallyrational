Create a complete, single-file HTML web application (HTML, CSS, and JS combined in one file) for a teacher-facing, interactive timeline ordering activity designed for screen sharing.

### 1. Visual & UI Architecture
- Dark/Modern EdTech Aesthetic: Slate/Navy dark background (#0f172a), high contrast typography, crisp rounded cards with soft shadows, and clean glassmorphism accents.
- Top Header: Includes the app title ("Elastic Timeline"), a "Pasting / Setup" modal button (gear icon or "Edit List"), a prominent "Check Timeline" button, and a "Reset" button.
- Setup Modal: 
  - Opens cleanly as an overlay/modal with a backdrop blur; must NOT take up permanent screen real estate.
  - Contains a large textarea where the teacher pastes line-separated events in correct chronological order (1 per line).
  - A "Load Activity" button that parses the text, assigns 1-based original index IDs, clears the timeline, and spawns the cards in the floating dock.
  - Automatically loads a default sample dataset on first visit (e.g., 5-6 historical or narrative events).

### 2. Floating Bottom Dock (Unplaced Pool)
- Occupies the bottom 35% of the screen.
- Unplaced cards float gently with subtle, continuous CSS drifting/hovering physics to feel alive and playful.
- Dragging a card out of the floating dock pauses its floating animation and makes it draggable.

### 3. Magnetic Top Timeline Rail (Continuous Field Physics)
- Occupies the top/middle 60% of the screen.
- Features a central horizontal line (the timeline stem) bounded by magnetic end-cap emitters on the left and right ends.
- Magnetic Field Repulsion & End-Cap Confinement:
  - Instead of clicking into rigid programmatic grid slots, cards on the timeline act like repelling magnets along the rail driven by a continuous `requestAnimationFrame` physics loop.
  - Both ends of the timeline exert an inward repulsive push so all cards stay comfortably on screen while naturally equalizing their spacing.
  - When a new card is dragged near or between existing cards, its magnetic field pushes neighboring cards outward smoothly as a continuous function of distance and proximity.
  - When a card is pulled off the timeline, the remaining cards smoothly flow into the vacated gap to fill the space evenly.
- Fluid Elastic Tether Hooks & Vertical Staggering:
  - Cards hook to the timeline stem via dynamic curved SVG Bezier tethers and sliding stem anchor nodes that flex with card velocity.
  - Cards alternate above and below the stem (with dynamic 2D anti-collision boost when crowded) so adjacent event text never overlaps.

### 4. Logic & Grading (Wordle-Style LIS Algorithm)
- When the teacher/class clicks "Check Timeline":
  - Read only the cards currently placed on the timeline stem from left to right.
  - Extract their original 1-based answer indices.
  - Compute the Longest Increasing Subsequence (LIS) of the placed cards.
  - Apply Wordle Color Coding:
    - GREEN (#22c55e background / glowing border): Cards that are part of the LIS (the correct structural backbone).
    - YELLOW / AMBER (#eab308 background / glowing border): Displaced cards that break the sequence and need to be moved.
    - GREY / DEFAULT: Cards left in the bottom pool remain neutral.
- If all placed cards form a perfect monotonically increasing sequence and all cards from the pool are used, trigger a subtle celebration particle/confetti effect.

### 5. Technical Requirements
- Standard Pointer Events (PointerDown, PointerMove, PointerUp) or HTML5 Drag and Drop for butter-smooth desktop and touch/stylus operation.
- Fully standalone: Zero external framework dependencies (Vanilla JavaScript, inline CSS inside `<style>`, pure HTML).
- Responsive: Recalculates canvas/bounds on window resize so cards stay within bounds.
- Make the code complete, production-ready, and fully contained within a single index.html file.
